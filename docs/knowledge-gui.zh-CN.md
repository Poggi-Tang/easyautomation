# 知识库管理 GUI

知识库按软件组织三类内容：**使用知识、控件库、组合动作**。使用知识描述软件怎么用；控件库保存定位、原生属性和学习参考图；组合动作引用这些控件，编排操作步骤及每一步的预期。

## 开发分支

GUI 开发集中在 `uiauto-gui` 分支，分支保留完整项目及 GUI 使用的知识库、定位、录制和后台任务模块。稳定版本经验证后再合并到 `main`；共享模块的改动和 GUI 一起维护，避免两套实现分叉。

在源码仓库中开发时：

```console
git switch uiauto-gui
python -m pip install -e ".[gui,image]"
python -m easy_uiauto.library_launcher
```

`gui`、`image` 依赖仍按需安装，基础自动化包不强制安装 Qt。界面入口位于 `src/easy_uiauto/qt_gui.py`，界面组件位于 `src/easy_uiauto/qt_ui/`，图标位于 `src/easy_uiauto/resources/icons/`，打包入口为 `scripts/build_library_exe.py`。EXE、构建缓存、模型和本机知识库不作为分支源码提交。

## 安装与启动

推荐直接拉取 `uiauto-gui` 分支，双击根目录的 **setup.bat**：

```cmd
git clone --branch uiauto-gui --single-branch https://github.com/Poggi-Tang/easyautomation.git
cd easyautomation
setup.bat
```

也可以在 GitHub 切换到 `uiauto-gui` 分支后选择 **Code → Download ZIP**，完整解压后双击同一入口。无需预装 Python 或开发工具。首次联网安装当前源码及完整依赖，默认保存到 `%LOCALAPPDATA%\easy-uiauto\gui`，然后创建桌面快捷方式并启动。首次安装会构建配置窗口并下载模型，耗时取决于网络；成功后重复运行会直接启动，源码变化后会重新安装。安装失败会保留错误提示，可重新运行。此 GUI 入口不注册 MCP、不修改用户 PATH、不安装 Codex/Claude Skills。

以后双击 **easy-uiauto GUI** 桌面快捷方式即可。拉取源码更新后再运行 `setup.bat` 更新安装。默认 `main` 分支不包含本 GUI 的一键入口，拉取时请明确选择 `uiauto-gui`。

需要离线分发时，使用构建得到的完整 `easy-uiauto-gui-win-x64.zip`。对方完整解压后双击 **setup.bat**，按 Windows 提示授权，即可创建桌面快捷方式并打开 GUI；移动解压目录后重新运行 `setup.bat` 更新快捷方式。

完整 ZIP 已包含 Python、Qt、CPU 图像运行环境、YOLO 权重及 OCR 检测/识别模型，本地学习和回放无需联网或预装 Python。缺少 Visual C++ 运行库时使用包内安装程序补齐。不要只发送 EXE。知识库默认保存到用户目录下的 `easy_uiauto_vault`，可在界面更改；导入参考资料、生成说明需要另外配置 API。

可选参数：`setup.bat -Target "D:\easy-uiauto-gui"` 指定源码安装位置，`-NoLaunch` 仅准备环境，`-NoShortcut` 不创建桌面快捷方式。完整 ZIP 直接在解压位置运行，不使用 `-Target`。`knowledge-library.cmd` 也调用此一键入口。

已有 Python 的开发者也可手动安装当前源码：

```console
python -m pip install -e ".[gui,image]"
easy_uiauto_library
```

完整功能安装 `easy-uiauto[full]` 也包含 GUI 依赖。主界面采用 PySide6 / QtWidgets；原生控件拾取、录制和高亮继续复用现有底层，在独立工作进程运行。

知识树、操作栏、菜单、步骤编辑和模型状态使用统一的 SVG 图标。对象类型与状态分别显示，按钮保留文字；下载/停止、启用/停用图标随状态同步切换。图标按显示缩放比例渲染，禁用时为灰色，深色选中背景上为白色。

已安装的开发环境中，可运行以下命令传入知识库路径：

```console
python -m easy_uiauto.library_launcher --vault "D:\UI知识库"
```

未指定 `--vault` 时读取已有知识库配置。顶部 **切换知识库** 只改变本次目录；**设置** 中可保存知识库路径、API URL、API Key 和 API Model。API Key 明文显示，模型支持输入和获取列表。区域标注使用本地 YOLO＋RapidOCR；导入参考资料的理解整理及资料辅助说明使用已配置的 API。

顶部 **标注模型** 会在启动时检查 YOLO 图形检测、OCR 文字定位和 OCR 文字识别三份模型，并显示就绪、待补齐或运行环境缺失。点击后每个模型只占一行，包含状态、文件路径和 **选择文件**。**重新检查** 可刷新状态，**下载 / 修复** 会在后台补齐缺失或损坏的文件，显示下载进度，并在下载后自动重新检查；下载期间同一按钮变为 **停止下载**。已通过 SHA256 校验的模型会复用。下载失败可重试，只有完整且校验通过的文件才会替换现有模型。EXE 使用完整目录中的 `_internal/image-runtime`，运行环境本身缺失时需要恢复完整发行目录。

路径支持 **选择文件** 或直接输入绝对文件路径。选择后自动保存；手动输入后按回车、移开焦点或关闭窗口时保存，并重新检查。检测、下载与实际标注共用此配置，重启后仍有效。文件尚未下载时，可先输入保存路径，再点击 **下载 / 修复**。清空输入并结束编辑即可恢复默认位置，不会移动或删除模型；默认路径显示在输入框中，悬停可查看完整路径。当前支持的模型版本仍为 OmniParser v2 `icon_detect_v3` 和 PP-OCRv6 small，选择文件后仍会检查对应版本的 SHA256。配置保存在当前用户的 `%LOCALAPPDATA%/easy-uiauto/model-paths.json`。

## 添加学习参考资料

展开 **软件 → 使用知识 → 参考资料**，点击 **添加参考文件** 或 **添加网页**。支持 PDF、Word `.docx`、Markdown、文本、HTML、XMind、FreeMind `.mm` 和 OPML。旧版 `.doc` 需先另存为 `.docx`。网页读取服务器返回的正文，登录后或依赖脚本加载的页面可先导出为 PDF、Word 或 Markdown。

首次导入会提取内容，使用设置中的 API 分段理解，并生成标准 Markdown。PDF 保留页码，Word 表格保留单元格关系，脑图保留分支路径；扫描 PDF 页使用本地 OCR。整理内容包含功能说明、别名、入口、前置条件、操作步骤、预期结果和原文出处。

标准文件保存在当前软件的 `references/`，原始文件副本保存在 `references/sources/`。选中参考资料即可编辑标准 Markdown，Ctrl+S 保存；后续学习直接使用这份修订后的文件。重复添加相同内容不会再次调用模型；**重新整理** 使用原始副本重新生成，覆盖前会提示。可 **停用参考** 暂停使用，或删除到归档。

长文档按段整理，已完成的段落保存在 `references/.imports/`。API 返回内容被截断时会自动拆小段继续；网络中断或某条引用核对失败时，重新添加同一文件即可继续。引用核对兼容 PDF 的排版空格、换行及全角字符，并保存对应的原文；无法核对的引用会从原文片段中自动重新选择依据，仍不通过则报告所在段落和条目，保留现有参考资料。**重新整理** 会主动重新请求全部段落。

补充说明时会先阅读当前软件的完整标准资料，归纳软件的对象关系、区域职责、功能流程、前置条件与操作结果，再结合控件标识、原生文字及所在区域，用自己的话编写功能说明。控件名不必在手册中逐字出现，也不要求说明复制原文。合理推断会保留推断依据；线索不足时显示待确认原因。

长资料的软件功能理解会保存复用，修改参考 Markdown 或启用的资料后会重新理解。已学习的控件可通过 **更多 → 补充控件说明** 更新，不必重新扫描或连接软件窗口。控件属性显示说明来源和推断依据，**更多 → 查看参考依据** 可打开原参考资料。生成说明不改变原生 Name、XPath、动作或风险规则，人工填写与实际交互观察的说明优先保留。

本地资料不再限制为 40 MB：文件分块读取、校验和归档，PDF 从磁盘按页提取，Word/XMind 只解析正文，不解压内嵌图片。网页下载上限为 256 MB，超出可先下载到本地再导入。单份 PDF 仍最多 1000 页，提取文字最多约 120 万字符；待解析的 XML/JSON/HTML 正文结构最多 200 MB，Word/XMind 内嵌图片不计入此大小。导入时会生成临时文件副本，结束或失败后清理。整理失败不会覆盖已保存的标准文件。基础扫描的说明补充失败时仍保存定位和图片，并在任务结果中报告原因。

独立目录版可在安装 PyInstaller 的构建环境生成：

```console
python scripts/build_library_exe.py --image-python "D:\本地标注环境\python.exe" --package-dir "dist\gui-release"
```

`--image-python` 指向已安装图片标注依赖的完整 Windows CPython 环境；构建时需已缓存官方 OmniParser 权重，也可用 `--image-weights` 指定。构建脚本将解释器、所需依赖、OCR 模型和 YOLO 权重复制到独立的 `_internal/image-runtime`，学习时才启动，不进入 GUI 启动路径。

生成 `dist/easy-uiauto-library/easy-uiauto-library.exe`。EXE 内置管理员权限清单，双击启动时由 Windows 请求 UAC 授权；授权后，管理器及其学习、拾取、录制和回放工作进程均以管理员权限运行。分发时保留整个目录，包括 `_internal/image-runtime` 和第三方许可文件。

使用 Python 3.13 构建。`--package-dir` 还会生成可直接分发的 ZIP 和 SHA256 文件，并附带 `setup.bat`、运行库安装程序及中文说明；该目录须为新的打包目录。打包前校验源文件、EXE 和三份模型，拒绝把 `--frontend-only` 构建当作完整包。GitHub Actions 的 **Build ready-to-use GUI** 工作流可手动选择 `uiauto-gui` 分支运行，下载产物中的 ZIP 后即可分发，无需先发布到 PyPI。

目录版不收集 MCP 服务端及旧版管理界面；MCP 服务仍从安装的 Python 包启动。打开主界面时按需加载依赖，录制、UIA 操作和图像处理底层在实际使用时加载。Python 原有导入方法保持兼容。

## 选择窗口与添加区域

1. 在知识库根节点点击 **添加软件**，从可见窗口列表选择软件，填写软件名称。已有软件使用顶部 **选择窗口** 重新绑定。
2. 在软件或控件库节点点击 **添加区域**。管理窗口最小化，目标软件激活。
3. 鼠标悬浮选择控件。红框标出边界，右上浮窗显示 AutomationID、Name、ClassName、ControlType。滚轮向上切换父节点，向下返回子节点。
4. 按 **Ctrl** 确认、填写区域名称；**Esc** 取消。确认前隐藏浮窗与红框，再保存区域图。确认不会点击目标控件。
5. 手动打开目标状态，选择区域，点击 **基本学习**。先截取区域，再用本地 YOLO＋RapidOCR 标注图形和文字，按标注中心调用录制底层的 `get_control_info(x,y)` 获取 UIA 属性及 XPath。已配置 API 时，结合截图、原生属性与参考资料分析语义；未配置时保存原生名称和可观察的信息。基本学习不执行区域前置步骤，不点击、输入或展开菜单。点击 **修改边界** 可重新拾取，保留区域 ID。

UIA 绑定成功时保存完整控件截图及原始 XPath 祖先链；Group、Pane、ToolBar 等布局容器只用于区域及定位上下文，不作为独立控件保存。没有独立 UIA 节点时保存标注区域原图、文字和坐标，LOCATION 中的 XPath 为空，并标记为图片定位；回放时在当前窗口中重新匹配模板，不构造虚假的 XPath。文字与图形共用同一个 UIA 节点时，文字仍作为独立观察保留。

标注图与坐标资源保存在软件目录的 `analysis` 下，控件的学习图片保持为未画框的原始裁剪图。标注失败会报错，不会自动改成整树采集。重复学习不因一次漏检隔离已有控件；旧整树学习产生的、未被其他知识引用的布局记录会移入 `.easy_uiauto/archive`，人工修改及被流程引用的记录保留。

左侧知识树支持 **Ctrl 点选多项、Shift 连选**。选中后点击 **删除所选**，或使用右键菜单、在知识树内按 **Delete**，确认一次即可批量删除。多选时编辑区暂停编辑，避免把修改写到其中某一项。软件、分类及只读区域节点保留；仅归档明确选中的区域和控件，未选中的子项继续保留。删除前置控件后，引用它的步骤或组合动作需要重新配置。

**查看区域** 位于软件、控件库和区域节点的操作栏，随时可返回查看当前保存的布局图及区域边界。总览中可切换区域状态、选择区域高亮，并点击 **修改所选区域** 返回拾取；查看本身不会刷新截图或操作目标软件。

当区域显示 **待确认** 时，点击 **基本学习** 会直接打开确认窗口。逐个检查该状态下的区域边界，正确后点击 **确认区域并学习**；有偏差则先修改。点击 **返回** 不会确认，也不会开始学习。

主窗口及其所属对话框均可拾取，不会绑定其他软件的同名窗口。没有合适 UIA 容器时，内部自绘元素不能凭空生成 XPath。

选择知识树节点只查看资料；**基本学习** 仅读取当前界面，**打开区域、深度学习、执行、运行** 会操作目标软件。窗口尺寸或类型变化后，区域需要重新检查并确认；边界有偏差时重新拾取。区域总览显示当前保存的布局，不提供历史截图撤回。

## 深度学习：探索区域内的业务流程

选择区域并点击 **深度学习**，填写学习要求和测试输入，例如 `{"工程名称":"学习测试","保存路径":"D:/测试工程"}`。程序读取区域说明、使用知识和启用的参考资料，通过配置的 API 规划交互；控件检测仍使用本地 YOLO＋RapidOCR。缺少 API 配置时会报错，不执行探索。

探索会逐个执行入口、观察操作结果、继续学习菜单或弹窗，并自动创建新状态的区域和控件。右键入口与普通点击分别记录。相同界面状态会复用已学控件和后续流程；不同输入值、选中状态或窗口内容不会仅凭标题相同合并。新区域出现在同一软件的控件库中，保留可编辑的名称、边界和首次进入路径。

确认业务结果后，程序自动生成组合动作。菜单栏、工具栏、右键菜单如果汇合到同一状态，会分别保存入口，并通过 **调用组合动作** 共享后续步骤。调用按 ID 解析最新定义；修改公共步骤会影响各入口，原运行记录会标为过期。删除被调用动作或形成循环时，流程变为待完善，不发送输入。步骤编辑器可添加调用、选择被调用动作，输入框中的 JSON 用于传递参数。

新建、保存等操作需要在学习窗口勾选 **允许新建、保存等测试数据提交**。缺少必要输入、拖拽等当前流程引擎不支持的动作、删除或外部发送操作均记录为未完成。探索优先使用明确的返回步骤；也可指定已有 **返回起点动作**。业务操作已经执行但无法确认返回起点时会停止，不能用重复创建或删除数据冒充返回。

默认预算为 100 个交互步骤、24 层状态，可调整。到达预算、无法返回或停止任务时，已入库知识保留；在 **使用知识 → 区域名 · 深度学习进度** 查看未完成原因，以及新增、更新、复用、待定位和待验证结果。

再次点击 **深度学习**，通过“本次目的”选择处理方式，并选择要接着使用的学习记录：

| 本次目的 | 处理方式 |
| --- | --- |
| 继续未完成学习 | 复用已完成分支，使用最新输入、要求和参考资料重新分析受阻、未执行成功的分支。改变输入不会另建一套记录。 |
| 改进学习结果 | 可以勾选控件或组合动作；不勾选表示整个区域。重新分析指定内容，保留原记录 ID，自动生成的动作就地更新。 |
| 适配软件更新 | 先打开并检查区域边界，再比较当前控件与已有记录，更新定位；通过相同入口到达的新界面继续使用原状态及区域 ID。 |
| 首次学习 | 新建独立学习记录；已有控件仍按身份合并，组合动作属于新记录。一般重学使用前三种方式。 |

上次操作结果不明时，列表会显示原因。可以手动打开已记录的结果界面继续后续操作；只有确认操作未生效或测试数据已恢复，才勾选该分支允许重试。到达某个结果状态后完成后续学习，若还有其他入口，界面会提示恢复原起点继续。不会通过自动重放提交来恢复进度。

人工控件名称、说明、归属和实际交互得到的效果说明优先保留。人工修改过的组合动作不会被自动替换；建议的新步骤保存在本次修订记录中，并在进度报告列为冲突。历史学习图保存在应用目录 `learning/history/`，修改前的控件和动作记录保存在 `learning/revisions/`。

适配更新时，没扫描到的控件标记为 **更新后待定位**，不会据此认定已经删除。未展开入口中的控件和扫描被截断的范围不会自动标记消失。引用变化控件的组合动作及其调用方标记为 **更新后待验证**。本次学习重新走通并通过结果校验的流程可直接获得验证记录；其余流程在能确认起点、步骤影响及预算时实际运行验证。需要提交测试数据但尚未允许、起点不符、缺少结果校验或定位不明的流程保留具体原因，可恢复条件后继续，或从组合动作执行并验证。验证后再次修改定义或引用定位，旧验证会失效。

学习完成指本次观察、规划范围内的分支处理完毕，不代表穷举任意文本值或所有业务数据。业务结果须通过实际校验；只点击过控件、打开过弹窗或达到预算都不算流程完成。

## 手动添加控件

在软件、控件库或区域节点点击 **添加控件**，也可使用右键菜单。将鼠标移到目标控件，滚轮切换父子层级，按 **Ctrl** 确认，**Esc** 取消；拾取不会点击控件。

确认后填写名称、说明和所属区域，再点击 **保存**。从区域进入时默认选择该区域；也可选择同一窗口的其他区域或“未分区”。Tab 状态分别列出，动态子区域同样可以添加。请先在目标软件中打开相应状态或菜单，再拾取其中的控件。

保存会保留原生属性、XPath 和控件截图，自动选中新控件；可在属性中继续编辑定位和前置步骤。新控件继承所属区域的前置步骤及展开路径。重复拾取同一状态、同一路径的控件会更新原记录，保留原 ID、别名和单独配置的前置步骤；名称和说明会先显示已有内容。取消填写不会写入控件。

此入口直接拾取 UIA 节点，不需要运行标注模型。没有独立 UIA 节点的自绘元素仍通过 **基本学习** 生成图片定位控件。

## 同位置的不同 Tab：添加状态

例如“工作区”在“主页”和“绘图”两个 Tab 中占据相同矩形。它们是同一区域的两个状态：

```text
软件
└─ 控件库
   └─ 工作区
      ├─ 主页
      │  └─ 主页控件
      └─ 绘图
         └─ 绘图控件
```

选中原区域，点击 **添加状态**，填写状态名称、前置步骤和状态条件，再拾取该状态的区域。

- **前置步骤** 可以是一条或多条操作。可选择已有控件、拾取入口控件，也可通过 **录制步骤** 记录后编辑。
- **状态条件** 选择 Tab 时使用“已选中”；其他情况选择该状态独有的控件，使用“控件存在”。不要使用所有状态都存在的外层容器。
- **打开区域** 先检查状态；未满足时执行前置步骤，再等待状态条件。不会自动重试已发送的输入。
- 状态拥有独立控件、页面和参考图命名空间。同一位置允许不同状态共存，重学其中一个不会覆盖另一个。
- 同一状态的区域重叠仍会提示；可选择更新已有区域、添加状态或取消。

区域的 **前置步骤** 页显示路径，点击 **编辑前置步骤** 调整动作、目标和顺序。控件默认继承区域及已学菜单路径；单独修改控件前置步骤后，保存的是该控件完整的覆盖路径。

## 菜单及展开内容

先学习菜单栏，选择“文件”，点击 **学习展开内容**。程序执行到该控件，读取展开菜单，不继续执行菜单中的业务命令。

展开内容保存入口路径；多级菜单可逐层继续学习。菜单容器自动组织为动态子区域，原控件记录与 LOCATION 保留。普通节点层级只组织知识，不会自动变成一次点击。

选中动态区域后，点击 **细分区域**，在对应的学习参考图内拖框保存子区域，可继续向下细分。
子区域必须位于父区域内，同级不能重叠。使用 **重新学习展开内容** 更新自动发现的控件；
**上级控件** 用于调整管理层级，不改变 XPath。已有动态区域的前置路径只读，入口修改在原控件中进行。

选择“新建”后点击 **执行**，先显示前置路径，确认后按路径操作。学习参考图始终保留菜单展开时的控件，运行画面独立保存。

## 跨区域组合动作

在软件下选择 **组合动作 → 新建**，填写标题。中心步骤表编辑动作和嵌套预期，右侧编辑当前步骤的目标、动作类型和值。

例如“新建工程”：

1. 检查工程树不含本次工程名称。
2. 点击菜单栏“文件”。
3. 点击“新建工程”，预期新建对话框存在。
4. 输入工程名称，预期输入框文本相等。
5. 点击“确认”，预期对话框不可见、工程树包含本次工程名称。

**添加动作** 从当前软件的控件库选择目标，可跨区域、跨主窗口和所属对话框。动作类型选择“检查”可插入仅读取状态的步骤。**添加预期** 将检查挂到当前动作下。

支持点击、双击、右击、输入、按键、组合键和检查。预期包括存在、不可见、文本等于、窗口标题、只读、菜单包含、Tab 已选中、包含 / 不含树节点。

**包含树节点** 在所选树容器内有界查找名称，不需要事先录制将来才出现的节点。达到节点、深度或时间限制会报告不能判定，不把读取不完整当作不存在。

点击 **参数** 配置参数名和默认值；编辑输入或预期时，**值来源** 可选择固定值或参数。运行前可修改本次输入。参数同时用于输入文本和预期，缺少参数在任何输入前报错。

需要某个目标的入口路径时，选择步骤后点击 **插入前置步骤**，预览后将路径明确插入步骤表。组合动作只执行表中步骤，不会每步再隐式叠加区域或控件的入口路径。

也可在“更多”中 **导入步骤表**，粘贴 Markdown 的“动作标题、前置条件、步骤、预期”表格；兼容旧“用例名称”表头。转换器处理不了的描述保留为待完善，不猜测执行。

## 让 Agent 按人工划分学习并归档

先在 GUI 保存区域名称、说明、前置步骤、状态条件及参考资料；待确认的区域需要先确认。
Agent 与 GUI 必须使用同一个知识库目录。可以把下面的指令复制给 Agent，替换方括号内容：

```text
使用 $easy-uiauto-learning。
知识库目录：[GUI 当前显示的绝对路径]；软件：[软件名称或 app_id]。
我已经手动划分区域。请先读取我的区域、说明、前置步骤、使用知识和启用的参考资料，
按这些输入逐个学习 [区域名称或全部已划分区域]，将控件归档到现有区域及对应状态，
保留我的区域 ID、边界、名称、说明和前置路径。
需要展开菜单时，沿已保存的入口学习展开内容并归档到对应动态子区域。
再将 [具体流程名称与操作要求] 保存到该软件的“组合动作”，绑定真实控件，
将可变输入参数化，加入前置检查和预期结果。缺少控件或依据时保存草稿并列出缺项。
先学习和保存定义，业务流程的实际执行验证由我另行指定。
最后列出归档的控件、组合动作、待完善项目和验证状态。
```

MCP 提供以下接口，直接复用 GUI 后端和文件格式：

| 接口 | 用途 |
| --- | --- |
| `get_ui_library` | 读取软件、区域、控件、参考资料、使用知识和组合动作，支持分页与指定知识库 |
| `get_ui_library_readiness` | 检查区域学习所需的本地模型及运行环境 |
| `start_ui_library_task` | 启动基本学习、深度学习、展开学习、参考说明补充或已保存流程的运行 |
| `get_ui_library_task` | 查询进度、结果与中断时的操作证据 |
| `stop_ui_library_task` | 停止本次任务，保留已保存记录 |
| `save_ui_workflow` | 保存组合动作定义；同名更新已有记录，缺项保留为草稿 |

学习任务立即返回任务 ID，Agent 持续查询该任务；等待超时后也查询原任务，不重复启动。
需要交互探索时，可以给 Agent 这样的指令：

```text
深度学习 [区域名称]，覆盖菜单、工具栏和右键菜单中的业务入口。
使用我保存的区域说明和参考资料；测试输入为 [名称、路径等实际值]。
通过 deep-learn-region 探索并归档新区域、控件和组合动作，公共后半段用调用引用复用。
允许新建和保存这些测试数据。无法返回时停止并保留进度，列出未完成分支。
```

同一个 MCP 服务同时只运行一个知识库任务。基本学习只扫描当前可见状态；深度学习和展开学习会操作区域或菜单。
请保持目标软件可见，避免同时在 GUI 和 Agent 中操作。纯参考说明补充不操作软件窗口。

组合动作的“可运行”表示定义与绑定通过检查，不表示已经执行验证。
实际运行通过 `run-workflow` 任务写入运行记录；修改定义后，旧结果会标记为需要重新验证。
Agent 写入完成后，在 GUI 保存当前未保存的编辑，再点击 **刷新** 即可查看。

这些接口需要运行包含本次改动的 MCP 服务及学习技能；已启动的旧服务需重启才能发现新工具。
独立 GUI EXE 不包含 MCP 服务，Agent 使用的是另行安装的 Python 包。

## 运行结果与保存

点击 **保存** 或 Ctrl+S 保存当前修改。切换节点、知识库或关闭时，对未保存内容询问保存、放弃或取消。

**运行** 先校验引用和参数，再在独立进程执行。每个输入动作只发送一次；只有定位和预期检查会等待。前台被其他软件抢占、定位失效或检查失败时停止，不会重复点击“确认”来重试。

**运行结果** 按动作和预期显示通过或失败。选中一项查看预期、实际值和截图；执行前、执行后、预期检查截图分别保存。点击 **返回步骤** 继续编辑。截图失败单独记录，不会重复动作。

学习参考与运行证据分开；普通执行不覆盖学习图、区域图或原有 XPath。最近一次组合动作结果保存在 `last_run`；修改流程或其引用定位后，旧证据需要重新验证。

学习和操作期间底部持续显示进度与 **停止**。停止或超时只回收本次工作进程，已保存记录保留；已经发送的输入不会撤销。

## 数据兼容与权限

重复扫描会保留软件的窗口绑定、自定义元数据及 `app.md` 正文。旧版本已经清掉的绑定，可在 GUI 重新选择窗口；MCP 也可从 `list_windows` 选定窗口，通过 `window_handle` 指定本次任务的目标。显式句柄不会改写长期绑定，已保存的窗口类约束仍然生效。

自动分页面扫描结合原生窗口身份、已检测的布局和图像边缘判断是否复用页面，不再仅按整图亮度相似度合并。无法确认同一页面时新建页面；模型生成的同名 ID 会自动避让。页面截图按内容保存，页面记录的前一版本保存在软件目录的 `history/pages/`。旧库缺少原生窗口身份时采用更严格的判断，不会仅凭 Qt 对象名合并页面。过去已经被覆盖、且没有备份的内容仍需重新学习。

窗口标题与 UIA 名称分别保存。旧控件的 UIA 定位仍可使用；MCP 效果学习在一次操作中按原窗口句柄和进程持续观察，窗口关闭时记录消失，不重新匹配同名窗口。若动作已执行但观察失败，会保存失败记录并提示不要直接重复动作。

单个控件的父子身份失效或元素消失，不会丢掉同批其他已验证控件；失败目标会保留为带原因的图片观察，不会生成未经验证的 XPath。权限不足、窗口失效等整体故障仍会停止任务。尺寸检查失败时会同时给出记录尺寸、当前可见帧尺寸和窗口句柄，便于区分窗口变化与偶发读取问题。

目录版 EXE 启动时会请求管理员权限。源码或 Python 命令启动不受 EXE 权限清单影响；若出现 **Windows 拒绝读取 UI Automation 控件**，请在管理员终端中启动，并与目标软件使用相同的运行账户。权限不足时，UIA 可能只能读取窗口外框或标题栏；这不代表软件内部没有控件。

定位失败时若记录的 UIA 根类与本次读取不一致，错误会显示两者。无权查询进程信息只表示权限状态未知，不会直接断定目标正在以管理员身份运行。现有区域和 XPath 会保留，先排查权限及所选窗口，再决定是否重新拾取。

现有 Markdown/YAML、PNG 与索引直接读取；原有控件 ID、LOCATION 和知识库目录保持兼容。展示名称与 UIA Name 分开；高级页可切换身份 / 位置模式并编辑定位信息。**验证定位** 仅读取，不会点击或解除隔离。

如果目标软件以管理员运行，管理器也应以管理员启动；普通权限进程无法读取部分提升权限的软件。窗口激活使用已验证的原生句柄，定位使用 UIA 名称，允许原生窗口标题与 UIA Name 不同。

导出软件知识得到 JSON，图片引用仍相对于该软件目录；完整搬迁需同时复制软件的图片目录。删除区域或控件使用归档方式保存 Markdown。


选中控件后，在 **高级 → 定位图片** 查看匹配模板、完整路径及图片变体。显式填写 `LOCATION.Img` 时使用该图片；留空时使用学习保存的控件图及变体，显式路径失效不会改用旧图。

**验证定位** 与 **执行 / 组合动作** 共用定位规则：先用 UIA；普通未找到时才用本地模板匹配。为获取当前画面，图片匹配会激活已连接的软件窗口。匹配须同时满足分数及唯一性检查，输入前重新检查目标，运行结果显示 `resolved_by`、匹配分数和坐标。参数错误、歧义、位置模式及索引失效不通过图片绕过。

图片目标支持点击、双击、右击及可见性检查；只读、选中、文本值等 UIA 属性预期仍需要真实 UIA 控件。执行截图单独存为运行证据，不覆盖学习参考图片。


操作前检查目标窗口是否被禁用，并根据同一进程的窗口所属关系列出阻挡弹窗；普通浮动面板不会仅因出现就阻断操作。目标明确属于弹窗时检查该弹窗，支持“主窗口 → 对话框 → 二次确认”的多层关系。发现阻挡时停止本次操作并打开弹窗管理，也可通过 **更多 → 处理弹窗** 主动检查。

在弹窗管理中选择 **查看弹窗** 切换到软件处理，或选择 **关闭所选弹窗** 发送一次正常关闭请求。不会自动选择确定、保存、放弃修改，不会强制结束进程，也不会自动重试原动作。关闭后如又出现保存确认，列表会显示新的阻挡窗口，由用户处理后重新执行。


**功能待确认** 表示控件用途尚未确认，不代表无法定位。用户在 GUI 中明确选择控件后，可按当前 UIA 定位或唯一图片匹配执行，图片观察也可独立作为目标；没有 UIA 属性时不构造虚假的 XPath。历史学习记录中的语义待确认状态不会阻挡手动执行，真实运行失败形成的隔离仍会阻止回放。
