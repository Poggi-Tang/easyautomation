# 历史学习知识修复与转换指南

升级 easy-uiauto 不会自动清理或转换整个知识库。先检查旧记录，再决定是修正说明、重建定位、补学操作，还是仅导入旧格式。填写下文方括号中的信息，就可以把提示词交给 Agent。

## 正确的记录长什么样

| 记录 | 应保存什么 | 不应当作依据的内容 |
| --- | --- | --- |
| 区域 | 归属页面及窗口范围（主窗口或所属弹窗），实际拾取的 UIA 控件属性或能在该范围唯一匹配的参考图。菜单和弹窗还要记录从哪个入口、经过哪些前置步骤进入；区分同一窗口内的不同状态。 | 旧坐标、旧窗口尺寸、区域宽高、兄弟序号，或者仅凭弹窗标题猜测它由哪个入口打开。 |
| 控件 | 稳定的记录 ID、所属页面及区域、真实的 `location`（原生 `LOCATION`，含实测属性和有效 XPath），以及可用的原始参考图。无 UIA 的目标可用唯一图片定位，不造假 XPath；查不到属性或唯一图片，就保留为待复核观察。 | 旧 `x/y`、框选位置、同名或相似图标；一张静态截图也不能证明控件可点击、可输入或可读值。 |
| 功能说明 | 用简体中文说明**做什么、作用于谁、何时可用**。例如：“在‘新建项目’对话框中设置待创建项目的名称，输入后仍需确认提交。”保留人工修订；真实 UIA `Name`、`AutomationId`、`ClassName`、`ControlType`、原始界面文字和业务值原样记录。 | “通过 OCR 识别为输入框”是采集来源，不是功能；“应该可以新建”不是实测结果。不要把中文展示名写回原始 UIA 名称。 |
| 组合动作 | 用 `target.control_id` 绑定真实控件，明确列出前置操作、动作顺序、输入参数、可观测的预期。保留被其他流程调用的 ID。 | 写死坐标、隐含菜单打开步骤、硬编码业务值，或把“点过确定／窗口关闭”当作项目创建成功。 |

对照 Markdown 的 YAML 元数据时，可查看区域的 `page_id`、`window_scope`、`location`、`image`，以及适用时的 `parent_control_id` 和 `entry_steps`；控件的归属看 `page_id`、`region_id`，展示用的 `semantic_name` 与 `location.Name` 分开。字段取值应来自当前库和真实拾取结果，不从示例编造。完整定位字段见 [LOCATION 结构](../README.zh-CN.md#隐私与安全)。

**属性优先，图片只在普通找不到时兜底，且必须唯一。** 区域属性有多个匹配时不能用旧序号挑一个，也不能扩大到整窗继续学。新版深度学习只在本次扫描、裁图和操作时计算坐标，不为新学到的区域或控件保存定位几何。旧手绘布局、基本学习和已有动态区域的划分仍可能使用 `normalized_rect` 等字段；不要全库删字段，也不要把布局框解释为新定位。

分开记录三件事：**用途是否确认、当前是否定位成功、实际业务效果是否通过**。参考手册或截图可说明预期用途，但不是本次执行证据。定位验证不点击，不代表业务通过；改动定位或流程步骤后，不沿用旧的验证结论。运行失败形成的隔离不能靠改说明、重建索引或手写“已验证”解除。

### 示例：文件 → 新建项目 → 输入项目名称 → 确定

先在菜单栏的区域中定位“文件”；“新建项目”是展开后的**菜单项**，不和工具栏同名按钮合并。“项目名称”和“确定”属于本次操作打开的**新建项目对话框**，不是主窗口控件。首次核对时可由用户手动打开对应界面；若要 Agent 打开菜单、按键或输入，另行限定允许的动作。只授权检查定位时，不执行下面的流程。

下例是组合动作定义，`example.*` 都是占位 ID，**不能直接入库执行**；须用目标知识库和窗口中实际核对过的记录替换。确认前检查项目名尚不存在，输入后检查文本，提交后核对项目树出现新项目。只有在授权的测试环境里完成提交且检查通过，才记录业务验证成功。

```json
{
  "keyword": "【工程管理】新建项目-文件菜单",
  "name": "【工程管理】新建项目-文件菜单",
  "precondition": "软件已启动",
  "steps": [
    {"id": "before-create", "action": "inspect", "target": {"control_id": "example.project-tree"}, "checks": [
      {"id": "name-unused", "kind": "node-absent", "target": {"control_id": "example.project-tree"}, "expected": "${项目名称}"}
    ]},
    {"id": "open-file", "action": "click", "target": {"control_id": "example.file-menu"}},
    {"id": "open-new", "action": "click", "target": {"control_id": "example.new-project-item"}, "checks": [
      {"id": "dialog-opened", "kind": "exists", "target": {"control_id": "example.project-name-edit"}}
    ]},
    {"id": "enter-name", "action": "set-text", "target": {"control_id": "example.project-name-edit"}, "text": "${项目名称}", "checks": [
      {"id": "name-entered", "kind": "text", "target": {"control_id": "example.project-name-edit"}, "expected": "${项目名称}"}
    ]},
    {"id": "create-project", "action": "click", "target": {"control_id": "example.dialog-ok"}, "checks": [
      {"id": "dialog-closed", "kind": "not-visible", "target": {"control_id": "example.project-name-edit"}},
      {"id": "project-created", "kind": "node-exists", "target": {"control_id": "example.project-tree"}, "expected": "${项目名称}"}
    ]}
  ]
}
```

`项目名称` 无默认值，运行时必须传入。文本和树节点检查需要可读取这些属性的真实 UIA 控件，不能用图片匹配证明文字或节点已正确写入。

## 哪些能直接改，哪些要重新验证

| 旧记录的问题 | 处理方式 |
| --- | --- |
| 说明里混入识别来源、界面原文被翻译，或说明写错了用途 | 根据可靠材料修正文案；实测属性只有找到可信原始证据才能还原。`teach_ui_control` 只用于人工确认的语义，不修定位、不解除隔离；不确定就保留待确认。 |
| 只有位置、旧序号、失效 XPath、丢失图片或匹配不唯一 | 让用户打开正确窗口和状态，重新拾取真实属性，或补采可唯一匹配的原始图。已有控件在 GUI **高级** 中修正定位，或用 `KnowledgeLibrary.update_control` 定向修改。用 GUI **验证定位** 复核；运行隔离另行用 `revalidate_ui_control` 显式复核，不批量解隔离。 |
| 区域归错、多个同名控件被当成一个、混入无关弹窗 | 核对页面、窗口归属、入口路径和受影响的流程再改；只看到同名不合并。缺少证据先保留，列出待复核 ID；确认无用且用户批准后再通过 GUI 归档。 |
| 旧记录写“已完成”，但搜索只聚焦未输入、只打开对话框、缺少提交结果，或结果不明 | 不能离线补成成功。保留已确认部分和缺失步骤，审查流程引用后按授权定向补学或验证。结果不明时先查当前状态；确认未生效或已恢复测试数据之前不重试。 |
| 旧控件还在独立 JSON/JSONL，不在当前库 | 走 [旧格式导入](shared-library.zh-CN.md#迁移旧数据)，用 `import_control_records` 先 `dry_run=True`，核对目标软件、页面、ID 和拒绝行，获批后再导入。保留原导出文件；导入不是修现有定位，也不会补造验证证据。 |

同一版本定向修旧结果时，GUI 选 **改进学习结果** (`improve`)，尽量选择具体控件或组合动作；已有会话只缺后续分支时选 **继续未完成学习** (`resume`)；软件版本确实变了才选 **适配软件更新** (`update`)。这些都是可能实际点击和输入的学习任务，不是离线转换；没有操作授权不要启动。保存组合动作不等于运行，人工修改过的流程不得自动覆盖。

## 可以复制给 Agent 的提示词

先用第一段拿到修复清单，再把批准的 ID 和权限写进第二段。若只想改说明，不必连接目标软件。

### 1. 只读盘点

```text
请按《历史学习知识修复与转换指南》盘点 easy-uiauto 的历史学习记录。
知识库 vault 绝对路径：[从 GUI 复制]；软件 app_id：[实际 ID]；
范围：[页面、完整区域 ID 或指定记录 ID]；软件版本：[已知版本；不确定则注明]。
先核对库路径和软件，不明确就停下来问我。读取 Markdown 原始记录，或用
get_ui_library 分页读取区域、控件、组合动作等；检查隔离项，并查同软件中引用它们的流程。
本步不修改知识文件、不重建索引、不导入、不解隔离，也不启动学习、点击或输入。
对每项给出 ID、原记录及证据、问题、受影响的引用、拟改内容，以及用途／定位／业务效果各自的验证状态。
区分「有证据可离线修」「需实机定位」「需授权运行」「信息不足先保留」。
说明哪些几何是传统布局所需字段，哪些旧深度学习几何不可信；不要按同名去重。
如果源数据是旧 JSON/JSONL，先列出拟导入范围和问题。只在获准的副本上运行 dry_run（工具可能创建锁文件），不写入正式库。等我批准后再改。
```

### 2. 按批准清单修复或转换

```text
修复 vault=[GUI 中的绝对路径]、app_id=[实际 ID] 下我批准的记录：[ID 与逐项改动]。
写入前暂停其他编辑或学习任务，在知识库外完整备份（含 Markdown、图片、流程、进度和历史证据），
并报告备份路径。重新读当前记录；与盘点时不一致就停止该项，不覆盖他人修改。
只修改批准的记录。保留已有 ID、人工修订、原始 UIA 属性和图片、归属与入口路径、工作流引用及原始失败证据；
只有清单明确批准且有证据时才更正其中相应的值。不要全库删坐标字段、同名合并、自动解隔离或编造验证。
优先使用 GUI / 共享库接口；修复后回读 Markdown，核对图片有效、引用完整、新旧差异只在批准范围。
如经批准直接编辑 Markdown，重载 GUI，检索前调用 rebuild_ui_knowledge_index；不要直接写派生索引。
如果这次是旧 JSON/JSONL 导入，只按我批准的预览导入，使用原来的源文件和目标范围，并报告逐行结果。
本次允许的实机动作：[默认无；如需要，明确准许的窗口、动作、测试数据、可否提交及恢复方式]。
未获授权不启动深度学习、不运行步骤、不点确定或保存；结果不明不重复提交。
输出每项的修改前后差异、引用/索引检查，以及用途、定位、业务效果三项证据；列出未完成项和补证条件。
```

需要保留审计记录时，另存盘点与修复报告，不把报告当作已验证的控件定义。若备份、库路径、归属或作用范围不明确，先停在预览阶段。
